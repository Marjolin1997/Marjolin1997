## 🧠 Engineering Principles

> Good software is not only code that works. It should be understandable, testable, observable, secure, and safe to change.

I try to keep my engineering decisions grounded in a few principles:

- model the domain before adding complexity;
- keep authorization and business rules on the server;
- prefer explicit, maintainable architecture over clever abstractions;
- design background work to be retry-safe and observable;
- treat database migrations and data integrity as first-class concerns;
- optimize only after understanding the actual bottleneck;
- keep deployment and production operations part of the engineering conversation.
